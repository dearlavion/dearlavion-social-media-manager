How to configure a project and add channels

A project is a separate brand/business using this tool — its own Drive folders, its own Buffer channels, its own set of social channels. Everything below happens on this dashboard; nothing needs a terminal.

1. Load projects

Fill in the repo Owner/Repo/Branch at the top (already pre-filled by default) and click Load projects. This works with no GitHub token, since the repo is public.

2. Pick a project, or add a new one

Back on the Dashboard, a row of project chips appears — click one to select it. To create a new project instead, go to the Set Up page (left menu) and fill in:

  • Project id — a short slug, lowercase, no spaces (e.g. another-brand). This becomes its folder name on GitHub.
  • Display name — whatever you want shown in the UI (e.g. Another Brand).

Creating a project needs a GitHub token (see below) — it writes a new config/<id>/channels.json to the repo, and switches you to the Dashboard with it selected. Set Up is also where you'll find instructions for connecting a posting tool (Buffer today).

3. Load its channels

Once a project is selected, a Load channels.json for … button appears. Click it to see that project's channel table (empty the first time).

4. Add a channel

Click Add channel, then fill in each field:

FieldWhat it is
EnabledWhether the hourly cron should pick this channel up automatically. Leave unchecked while testing — the per-row Post now button ignores this anyway.
IdA unique name for this channel within the project, e.g. ig-main.
PlatformLabel only, for your reference — the real destination is set by Posting tool + its ID field below.
Posting toolWhich backend actually publishes the post. Buffer is the only one implemented today; more can be added later without changing existing channels.
Interval (h)How many hours must pass since the last post before this channel is due again.
Drive folder IDThe Google Drive folder this channel pulls images from — the long id from the folder's share URL.
Buffer channel IDWhich connected account in Buffer to publish to. Look it up via Buffer's GraphQL API (see the README's Buffer section for the exact query).
IG post typeInstagram only — post, story, or reel. Defaults to post.
Caption templateDefault caption text. Drop a <image-filename>.caption.txt file next to an image in Drive to override it for that one post.

5. Save

Click Save to GitHub. This needs a token too. Everything on this page only ever reads or writes what's actually saved on GitHub — edits here aren't used by anything until you save.

Getting a GitHub token

Anything beyond loading (Save, Add project, Post now) needs a fine-grained Personal Access Token:

  1. github.com → your avatar → Settings → Developer settings → Personal access tokens → Fine-grained tokens
  2. Generate new token
  3. Repository access → Only select repositories → this repo
  4. Permissions → Contents: Read and write and Actions: Read and write
  5. Generate, copy it, paste it into the GitHub token field on this page (it stays in this browser tab's session storage — never sent anywhere but api.github.com)

6. Test it

Two ways to trigger a post without waiting for the hourly cron, both requiring the token above:

  • Post now (per channel row, next to Remove) — forces just that one channel, ignoring its Enabled checkbox and interval entirely. The fastest way to test a single new channel.
  • Post now (all channels in …) — runs the same sync-then-post flow for every enabled, due channel in the currently selected project only.

Either can take up to a couple of minutes — the status message at the top updates as each step (sync, then post) finishes. If a channel needs an image and none has been synced from Drive yet, it'll say so instead of posting nothing silently.

Common gotchas

  • The repo must stay public — Buffer fetches images from a public GitHub URL, not a binary upload.
  • A 401 on Save/Post now almost always means the token field is empty or missing the Actions permission.
  • A 403 on Save usually means the token's repository access was left on a read-only default when it was created.

Using the Scheduler (reminders)

Scheduler (left menu) is a personal reminder calendar, unrelated to any project. It doesn't send its own email — it reuses GitHub's built-in workflow-failure notification, since that's already something GitHub emails you for free.

How it works

  1. Click a day on the calendar, set a time, type a message, click Add.
  2. Click Save to GitHub — nothing is real until you save, same as everywhere else in this app.
  3. .github/workflows/reminders.yml runs every hour. If a reminder's date/time has passed and it hasn't fired yet, the workflow logs it clearly, marks it notified, commits that, and then deliberately fails the run.
  4. GitHub's own "workflow run failed" email notification fires because of that failure — nothing custom-built.

The one real limitation

GitHub does not let a workflow put custom text into that notification email's body — it can only say a run failed, with a link. Your actual reminder message is only visible by clicking through to the failed run and opening the Check reminders step's log, where it's the first line, clearly marked. This is a trade-off for using a free mechanism that already exists rather than adding a whole email-sending service.

Also check github.com/settings/notifications → the Actions section has email notifications enabled (usually on by default for repos you own) — otherwise GitHub won't email you about the failure at all.
